# P3 changelog

## 2026-10-28

- Added a fail-closed production guard to the text, synchronous file, and async job scan routes. Until P2's verified principal and tenant-resolution contract is integrated, these routes accept caller-supplied IDs only when `APP_ENV` is explicitly local development; the queued upload worker also stays disabled outside that mode.
- Added atomic async queue limits (100 pending jobs, 25 per organization, 5 per user, and 512 MiB of queued upload bytes) with HTTP 429 and `Retry-After` when full.
- Added a request-body cap before multipart parsing for file upload routes (25 MiB file allowance plus 1 MiB multipart overhead), covering both declared `Content-Length` and streamed requests.
- Added dedicated Fernet-key configuration for queued uploads, with bounded previous-key rotation support and legacy service-role-derived decryption for existing local queues.
- Hardened Git-history scan process cleanup so limit-triggered scans stop the `git rev-list` subprocess before waiting, avoiding pipe backpressure and Windows checkout-lock leaks. Event timestamps now use timezone-aware UTC values.
- Updated backend setup notes to distinguish local developer use from production deployment and corrected the stale P3 status summary.

## 2026-10-11

- Implemented the W1-8 ingestion slice: bounded extraction, PDF/DOCX/XLSX/PPTX and OCR, archive safety, persistent scan jobs, progress/cancel/restart handling, and file-scan UI. See `p3-implementation-status.md` for verification evidence.
- Started W9-11 browser extension core ahead of the calendar window: managed policy schema; background-only bearer-key requests; AI destination normalization; reduced host permissions; paste, file selection, drop, and form-submit capture; local non-sensitive activity; deployment package builder and tests.
- Added separate Chrome, Edge, and Firefox package targets. Firefox output uses an event background script, stable gecko ID, desktop data-collection declaration, and Mozilla managed-storage deployment notes. Generated all three manifests and validated their target-specific fields.
- Added Windows source-ZIP packaging for all three browser targets. Generated the Chrome, Edge, and Firefox ZIPs and inspected each archive; each contains only the nine extension files, with no `.env`, tests, or dependencies.
- Rebuilt the local-development ZIPs against `http://localhost:8000` and the default AI destination allowlist. These are not production packages; the current backend still does not implement the extension's API-key contract.
- Added a chunked content-script-to-worker file transfer; the worker submits multipart jobs, polls progress/results, and cancels an unfinished job when the page disconnects. Binary uploads up to 25 MiB use the async extractor route. Mocked tests verify the file bytes, bearer header, and absence of client tenant IDs. Live use remains pending P2 authentication for all scan-job routes.
- Fixed the file path to apply managed fail-closed behavior even when the API key is missing; added a regression test.
- Hardened fail-closed behavior when configuration storage cannot be read or an extension context goes stale, and bounded oversized paste/form text with the cached organization policy.
- Corrected W7-8 recovery to match the P3 exit test: queued jobs remain queued; running jobs are marked interrupted after restart, retain partial results/progress, and erase their encrypted upload. The dashboard now presents the interrupted state and rescan instruction.
- Updated the dashboard build/runtime image to pinned Bun 1.4.3 after verifying Bun 1.2.5 exposed Node v22.6.0, below Vite 8's supported minimum; the dashboard Docker image now builds without the Node-version warning.
- The API-key authenticated scan flow is waiting for P2 to resolve tenant identity server-side. See `extension.md` before attempting an integration test or deployment.
- Added folder-drop detection to the browser extension. Until recursive directory scanning is implemented, detected or unreadable directory entries follow the configured fail-closed/fail-open policy; tests cover both policy outcomes.
- Fixed the popup protection toggle to read the effective worker config and save to local storage (the same source used by scans); managed toggles are now read-only. Rebuilt all three development packages; the extension suite has thirteen passing tests.
- Hardened ZIP/TAR member collision checks to reject case-insensitive path collisions, preventing ambiguous results on Windows; the backend suite now passes 39 tests (1 platform-specific OCR test skipped on Windows).
- Added English/Hindi-aware PDF OCR with grayscale/autocontrast preprocessing and a Docker Hindi trained-data package; added tests for language selection, preprocessing, and missing language data. All 41 backend tests, including real OCR, pass inside the Docker image; its Tesseract language list includes `eng` and `hin`.
- Started W15-17 GitHub App work with RS256 JWT signing, raw-byte SHA-256 webhook signature validation, and a least-privilege installation-token exchange that scopes permissions and can restrict repository IDs. Credential persistence remains delegated to P2's vault. Five new unit tests cover JWT claims/signature, invalid inputs, webhook verification, token request scope, and sanitized errors. The full backend suite now passes 46 tests in Docker, including real OCR.
- Began the W18-19 repository working-tree service: shallow clone transport keeps the installation token in a Git HTTP header passed through process environment, scan limits and `.dlpignore`/default exclusions are applied, supported files use process-isolated extraction, and temporary checkouts are removed with Windows read-only cleanup handling. Results include the commit SHA and partial-limit reason. Seven service tests use synthetic files and mocked clone transport; live App, route, and P2/P4 integration remain pending. All 53 backend tests pass inside Docker, including real OCR.
- Added signed `POST /webhooks/github` intake. It caps bodies at 2 MiB, checks HMAC before parsing, persists only allowlisted installation/repository/ref metadata, deduplicates by delivery ID and verified-signature fingerprint, caps the queue at 10,000 pending events, and recovers in-flight items after restart. Ten new tests cover bad signatures, malformed events, body limits, ASGI routing, replays with changed delivery IDs, metadata-only storage, queue capacity, and recovery. The queue consumer, GitHub install lifecycle, scan trigger, P2 vault integration, and P4 incident handoff are still pending. The complete backend suite now passes 64 tests in Docker, including real OCR, the mounted webhook ASGI test, and app startup/lifespan.
- Added the W20-21 history-scanning service for added-line detection with commit/author/date/line provenance, per-scan blob dedupe, resume cursors, force-push restart detection, LFS/submodule/symlink skips, and explicit partial status for shallow clones or scan limits. Four synthetic Git repository tests cover a deleted secret, resume, rewritten history, `.dlpignore`, and LFS pointers. It remains a library slice: full-history fetch, P1 finding fingerprints, P2 scan/gate adapter, webhook queue consumer, and P4 incident creation remain open.
- Added the Git executable to the backend Docker image after container verification found it missing. The rebuilt image passes all 68 backend tests, including the Git history fixtures, real OCR, mounted webhook ASGI request, and app startup/lifespan. The Windows run also passes 68 tests; three ASGI/OCR checks are skipped there because they are exercised in the Linux container.
- Started W22-25 developer tooling with an offline CLI scanner over the existing bounded extractors and P1 detection entry point, plus SARIF 2.1.0 output that excludes matched content. Added optional finding offsets and populated them for built-in regex and Presidio results so SARIF can point to line/column. This initial slice has no organization-specific rules, pre-commit, GitHub Action, PR annotations, or VS Code integration yet.
