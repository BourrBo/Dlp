# P2 Contracts v1 baseline

**Version:** 1.0.0
**Status:** proposed implementation baseline; owner and cross-stream review remain open.
**Scope:** P2 service and persistence boundaries only. This document does not assign
P1, P3, or P4 implementation work and is not a production-readiness statement.

The canonical definitions are the Pydantic models in `backend/app/contracts/` and
the generated JSON Schemas under `contracts/schemas/`. Models inherit
`ContractModel`: unknown fields are rejected and model instances are immutable. The
generated schema manifest remains `PROPOSED`. JSON schema snapshots should be
regenerated with `python scripts/export_contract_schemas.py` when a model changes.

## Scan and decision contracts

| Model | Required fields | Optional/default fields and constraints |
| --- | --- | --- |
| `ScanRequest` | `channel`, `content` | `request_id` UUID generated by default; `destination` optional, <=2048; `requested_at` UTC now by default; `context` defaults empty and accepts string, integer, or boolean values. `content` is `SecretStr`, ephemeral, and must not be logged, persisted, or returned. |
| `Finding` | `finding_id`, `data_type` (1..128), `classification`, `severity`, `confidence` (0..1), `detector` (1..128), `masked_evidence` (<=512), `first_seen_at` | `event_id`, `fingerprint` (<=256), `location`, `policy_action`, and `last_seen_at` optional; `status` defaults to `open`. Raw evidence is prohibited. |
| `Event` | `event_id`, `organization_id`, `request_id`, `scan_id`, `channel`, `decision`, `reason` (1..2048), `finding_count` (>=0), `occurred_at` | `destination` optional, <=2048. Durable scan decision record; no raw content field. |
| `ScanResult` | `scan_id`, `request_id`, `decision`, `reason` (1..2048), `completed_at` | `findings` empty tuple by default; `policy_version` optional, <=64. |

P04 owns the scan orchestration producer. The request tenant is supplied by the
authenticated `Principal`, never by a client-controlled tenant field. Finding,
event, and result consumers are the P2 scan pipeline, persistence, and gate/API
responses. Extractor/detector/classifier/scorer/fingerprinter/suppressor/policy /
enforcer/recorder/alert/audit/finding-store protocols are defined in
`backend/app/scan/interfaces.py`; raw request content may only be passed transiently
to the extraction/detection stages.

| --- | --- | --- |

## Policy, action, and approval handoffs

`Policy.conditions` accepts only allowlisted keys: `channel`, `destination_class`,
`user_group`, `data_type`, `classification`, `volume`, and `file_type`. Each condition
may be a scalar or a non-empty list with at most 100 values. Channel, destination
class, role, and classification values use the enums/vocabularies above. Data and file
type strings are non-empty and <=128 characters; volume is a non-negative integer.
Unsupported keys and values fail validation.

The pipeline protocol contracts in `backend/app/scan/interfaces.py` are:

- `Extractor.extract(ScanRequest) -> str` and `Detector.detect(str, ScanRequest) ->
  Sequence[Finding]`.
- `Classifier`, `Scorer`, and `Fingerprinter` each transform a sequence of findings.
- `Suppressor.suppress(findings, Principal)` returns findings or a
  `SuppressionOutcome(findings, applied_ids=())`.
- `PolicyEvaluator.evaluate(findings, request, principal)` returns a `PolicyAction`
  or `PolicyDecision(action, reason, policy_id?, policy_version?, matched_conditions=(),
  evaluation_trace=())`.
- `ScanStartSuppressor` and `ScanStartPolicyEvaluator` add an explicit scan start time
  to their respective input; the former returns `SuppressionOutcome`.
- `Enforcer.enforce(decision, findings) -> PolicyAction`;
  `Recorder.record(request, principal, result, reservation) -> None`;
  `AlertSink.emit(request, principal, findings) -> None`;
  `AuditSink.record_scan(principal, request_id, decision) -> None`; and
  `FindingStore.store(principal, findings) -> None`.

P07 internal action types are `ActionPlan(action, status, requires_approval)` and
`ActionExecutionResult(status, detail)`, each field a string/bool as shown by the
dataclass definition. The P07 HTTP models are `ApprovalCreate(request_id, action,
justification, policy_id?, policy_version?)`; action is one of `redact`, `quarantine`,
`revoke_share`, `user_override`, justification is 1..1000 characters, and an optional
policy version is >=1. `ApprovalDecision.reason` is optional and <=1000 characters.
`ApprovalView` contains approval/action/request IDs, action/action status, approval
status, justification, requester, expiry, and creation time; `decided_by`,
`decision_reason`, and `decided_at` are optional. `ActionView` contains action/request
IDs, optional policy ID/version, action, status, justification, and create/update
times. These status fields are currently strings rather than closed enums.

## Connector and OAuth contracts

The provider-neutral P16 models use `extra=forbid` and immutable Pydantic records.
`ConnectorIdentity` requires connector and organization UUIDs plus provider matching
`^[a-z][a-z0-9_]{1,31}$`. Its tenant comes from the authenticated Principal. Connector
status is `disconnected`, `connecting`, `connected`, `degraded`, `reauth_required`,
`error`, or `disconnecting`; capability is `sync`, `exposure_detection`,
`revoke_share`, or `quarantine`. `ConnectorHealth` carries identity/status and optional
`last_sync_at` and `last_error_code` (<=64).

`SyncRequest` includes identity, optional checkpoint (<=2048), and `max_changes` (1..
1000, default 100). `DriveObject` includes `object_id` (1..1024), name (<=1024), MIME
type (<=256), optional non-negative size, modified time, HTTPS/HTTP view URL, shared
drive and shortcut identifiers (<=1024), `is_shortcut=false`, `removed=false`, and a
tuple of normalized permission dictionaries. `NormalizedChange` pairs an object with
`created`, `modified`, `deleted`, `restored`, or `permission_changed`.
`SyncResult` carries changes, optional checkpoint (<=2048), and `has_more`;
`InventoryPage` carries objects and optional next-page token (<=2048).

`Exposure` requires an object ID (1..1024), kind (`private`, `users`, `domain`, `link`,
`public`, `unknown`), and optional principal/permission ID tuples.
`ShareRevocation` requires object and permission IDs (1..1024). `ActionResult` contains
`succeeded` and an outcome string (<=64). The `Connector` protocol exposes
`connect/status/disconnect(identity)`, `sync(SyncRequest)`,
`detect_exposure(DriveObject)`, `revoke_share(ShareRevocation)`, and
`quarantine(object_id)`.

The persisted OAuth transaction binds state, verifier, organization, principal,
provider, optional connector binding/role/member/session/auth method, scopes, redirect
URI, and expiry. PostgreSQL stores a state digest and enforces tenant RLS; consumption
is atomic and one-time. The callback revalidates active membership/session before
provider exchange or failure mutation. OAuth error responses use generic invalid or
expired state and provider-failure messages; no tokens are part of the response.

Route authorization, API-key scopes, tenant filtering, and RLS remain separate
enforcement layers; a valid contract does not authorize access.

There is currently no shared `ExportRequest` Pydantic contract. P14 export route
parameters and response projection are route-local implementation details and should
not be represented as a shared or externally approved schema.

## Public v1 and internal handoffs

The implemented public v1 surface is read-only `GET /api/v1/policies` and
`GET /api/v1/policies/{policy_id}`. It accepts bounded pagination (`limit` 1..100,
`offset` 0..1,000,000), optional `enabled` and `action` filters, and returns the
explicit `PublicPolicy` projection (`id`, `name`, `enabled`, `priority`, `action`,
`version`, `created_at`, `updated_at`) inside a page with `limit`, `offset`, and
`total`. It requires a service/API-key principal with the existing `identity:read`
capability. Public errors use stable `error.code`, `error.message`, and
`error.request_id`; they do not expose validation input or internal exception data.
The public error vocabulary maps HTTP 400/401/403/404/409/422/423/429/500/503 to
`bad_request`, `authentication_failed`, `authorization_failed`, `not_found`, `conflict`,
`validation_failed`, `resource_locked`, `rate_limited`, `internal_error`, and
`service_unavailable`. Other statuses use `request_failed`. The request ID is nullable
and is also returned in `X-Request-ID` when the request middleware supplied one.

P07 action handoffs are internal dataclasses, not public API contracts:
`ActionPlan(action, status, requires_approval)` and
`ActionExecutionResult(status, detail)`. `ActionExecutor.execute` receives an
idempotency key, action, and safe metadata. No executor response may claim an
external action succeeded unless the configured provider confirms it.

## Versioning and compatibility

This is a proposed v1 baseline, not a frozen cross-stream agreement. Changes to
required fields, enum values, tenant semantics, secret handling, or response
envelopes are breaking and require a new version or explicit owner-approved migration.
Additive optional fields may still affect strict consumers because unknown fields are
forbidden; producer and consumer compatibility must be checked before release.
The `contracts-v1` Git tag identifies this repository snapshot only; it does not
signal approval by P1, P3, P4, or an external owner. Review status is tracked in
[`contracts-review-checklist.md`](contracts-review-checklist.md).
